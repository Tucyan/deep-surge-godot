# 结算页面与记录契约

2026-10-14。执行依据为 [结算评分](../core/settlement.gd) 和 [运行统计](../core/run_statistics.gd)，本文件描述 Godot 实际实现；原V0.2设计稿未随当前仓库提供。评分版本 settlement-score-v2、统计版本 run-stats-v1、奖励版本 completed-nodes-v1；权重与评级仍为试测参数。

## 页面

日志与分析两页均在页头右上提供 X 关闭，关闭后执行 settlement_exit 返回首页；结算分析页底部在“回看航海日志”右侧提供“结束”按钮，点击同样返回首页。日志回看、标签切换和长按行为保持不变。

finished 或 chapterComplete 成功事务结束后，GameSession 冻结 state.settlement，flow_app 显示独立结算页，隐藏航行场景与旧HUD。第一页日志以24逻辑像素/秒播放，鼠标左键/触摸按屏幕空白或日志区域、或按空格超过0.35秒加速至6倍。释放、失焦、退出及换页清除按压；按钮区域不触发加速。支持暂停、回到开头、手动滚动与直接查看结算。初次播放到末尾2秒后自动进入第二页。

第二页显示真实结局、评分四项、涌潮点和统计。详情保留分数/卡牌/战斗与危机/生存与木筏/航行与剧情五个分类标签；每类完整展示全部条目，超出面板时纵向滚动，支持滚轮、拖动滚动条及触摸滚动，不再提供上一页、下一页和页码。切换分类回到该分类顶部，概要、分类标签及底部“回看航海日志”和“结束”按钮固定在详情区域外。返回第一页默认暂停在开头，重新播放也不自动跳页。第二页保留空格触发聚焦按钮的正常行为。

主游戏原航行日志按钮、logs命令入口、paged_reference日志内容已移除，日志内容继续由核心记录。2026-10-17：首页“回溯潮涌”定位为[剧情回廊](story-gallery.md)，不再显示最近报告或结局清单。终局仍自动显示两页结算；核心继续保存 last_settlement，新开局不删除它，但该字段不再拦截回廊入口。独立 Galgame Demo 的对白 LOG 与任务/线索页继续保留。

## 规则与报告

新增 core/run_statistics.gd 采集实际卡牌流转、属性有效变化及溢出/来源、实际访问、战斗结果/回合、危机出口、设备及格子的作用/产出、筏格历史与成功行动。Inventory 数量变更统一记录去向，回牌出拳计使用不计消耗；费用、部署、弃置及临时清理分开，贝币单列。未成功的事务连同统计回滚。

结构化事件带全局序号、命令序号/子序号、run_id、实际节点/战斗实例和来源；run_id由基础设施Crypto产生，不消费规则随机。分数由core/settlement.gd纯函数计算，四项各自四舍五入后求和。危机映射明确为真实战斗节点、storm两个变体和剧情最终处理；贸易/休息/补给没有危机记数。入战前离开有节点危机失败，尚未进入的候选不记。风暴固定损伤但取得目标为成功，沉底货舱随机破损出口为失败；章节A/B/C按各自公开方案目标记成功，SOLO无危机事件。

报告含模式/出身/种子、范围、真实结果、完成量、计算版本及原始量、四项分数/评级、统计/卡牌/日志/终点属性快照、公开剧情路线/线索/任务及方案损失、点数明细。终局报告在当前命令所有实际效果与统计提交后生成；finish内部仍按原规则发节点点数，页面不发点。读档恢复报告，UI只读深拷贝，不重算旧报告。

chapterComplete保持活动局，只展示章节成绩与待结算节点，实际发点为0。之后主动结束整局会保留state.chapter_report，新整局报告同时带此前章节评分摘要，整局点数按累计completed只发一次。章节成果不冒充survived。

## 存档

实际Godot版本升级为schema=2、content_version=godot-flow-v02-4，规则随机仍为xorshift32-godot-v1，内容表及指纹算法未改。snapshot增加last_settlement，与当前state/profile在同一JSON中原子写入。此版本与V0.2文档的目标schema3不是同一协议。

旧godot-flow-v02-3/schema1档及上一版v02-2挑战档仍走明确兼容路径。缺少历史统计的旧局从恢复处开始记录，complete=false；页面注明统计覆盖范围，显示已知终点属性和原日志，正式分数不提供。旧终局awarded=true不重复发点。新版本拒绝空的当前终局/章节报告、异常计数、重复身份/成果、分数公式或进度矛盾等损坏字段，恢复失败保留原存档及当前会话。

## 2026-10-17：取消结算分数上限

当前内容版本 godot-flow-v02-21，评分版本 settlement-score-v2，schema 仍为2。探索与建设改为 `round(推进比例 × 25 × max(成果标签数, 0))`，取消原最多4项的截断；总分继续由四项相加，可超过1000。现有五种有效成果全部达成、满推进且其余三项满分时为1025分；这是当前成果集合可取得的分数，不是新增上限。推进比例、成功率、生存比例仍按原规则计算，零推进仍为0分。评级阈值和节点涌潮点发放不变。

结算页探索项移除 `/ 100` 并标注不封顶。旧内容版本存档及旧评分版本报告明确拒绝，不迁移或重算；同版本JSON恢复继续校验完整报告。无新图片资产，`ui.settlement` 登记版本与源文件hash同步更新。验证见[取消评分上限验证](../evidence/settlement-uncapped-verification.md)。
