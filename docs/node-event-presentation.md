桌面是三栏（立绘 | 文本 | 选项）；手机自2026-10-20起改为两栏：插画铺满整块面板作底图，事件文字压在面板左下的半透明底板上，右侧仍是选项栏。详见[手机阅读布局](mobile-ui-readability.md)。

节点事件在story阶段自动显示，不需要点击右侧入口。flow_app把全视口纯色遮罩和事件页插入世界与HUD之间，并按 z 序分三层：

| z | 层 | 内容 |
| --- | --- | --- |
| 0 | 世界与随世界走的操作 | 3D 海面/木筏、打捞 · AP1 |
| 1 | 事件底板 | `NodeEventSurface` 半透明纯色 + 事件页（桌面三栏，手机为合并面板加选项栏） |
| 2 | 常驻 HUD | 顶栏、菜单、环境状态、手牌顶栏与手牌、合成/转化（手机在事件阶段隐藏后三项） |

左侧竖排的视角复位、视角切换与遗物仓库入口（`CollectiblesEntry`）在事件阶段隐藏，与战斗阶段一致：它们所在的位置已经属于事件面板本身，浮在底板上会压住插画和文字。隐藏期间 `focus_mode` 设为 `FOCUS_NONE`，离开事件进入航行阶段时随 HUD 重建恢复可见与可点。打捞（`SalvageEntry`）仍保留原做法——继续绘制在世界层，被底板压暗并挡住输入，`focus_mode` 为 `FOCUS_NONE`。

手机的事件页自2026-10-20起覆盖到视口底边，手牌区让位：手牌托盘、手牌顶栏（行动点与容量徽标）和右下「合成/转化」入口在story阶段隐藏，离开事件后重建恢复。桌面保持原样——事件栏止于手牌顶栏上方（底边距视口328），行动点、手牌与合成入口仍可见。顶部状态栏、菜单、环境状态两端都保持可用。

事件页自2026-10-18起为三栏；手机自2026-10-20起把立绘与文本合并为一块面板：

| 栏位 | 节点名 | 内容 |
| --- | --- | --- |
| 立绘 | `NodeEventArt` | 事件插画，按内容字段→怪物图→节点类型→剧情场次映射；桌面是独立栏，手机是整块底图面板 |
| 文本 | `NodeEventProse` | 小标题、事件标题、事件说明/结果；预选时改为选项标题与选项说明；桌面是独立栏，手机是底图面板左下的半透明底板 |
| 选项 | `NodeEventOptions` | 只放按钮，不再显示标题和说明 |

桌面三栏共用同一事件容器：左右各留56，普通事件顶边124，教程事件顶边226为提示条留位；底边距视口328（避开行动点与手牌）。桌面立绘与文本按0.94比1.06分配剩余宽度，选项内容宽332加边框内距。

手机只有两块：左边整块面板用插画作底图（`STRETCH_KEEP_ASPECT_COVERED`），右边是宽420的选项栏。事件页外边距收到左右20、顶边64（教程事件108，给提示条留位）、底边12，面板因此由1568×578变为1640×644。文字底板在面板左下：不透明度0.70、圆角10、1px淡白描边、内距18×14；宽度取面板42%（收敛在300～760逻辑像素），高度随文字自适应；文字超出面板高52%时底板先加宽到62%再测一次，仍超出则封顶在52%高并可用手指上下滑动，底边渐隐提示还有更多；手机不画滚动条，选项栏内容照旧在栏内滚动。窗口使用 canvas_items 拉伸并随UI缩放调整可用逻辑尺寸。

立绘不做强制美术约定：先读 `node.art` / `scene.art`，该 AssetId 若没有实体文件（占位）就跳过；其次按 `node.monster` 取 `enemy.*` 怪物图；再按节点类型取剧情插画（`opening.image.*`，读 `scenes.json` 的 display_region 裁掉原图自带黑边）；最后回落到默认海面插画。剧情场次另有 `ART_BY_SCENE` 覆盖表。v27的10个寻物节点已用 `node.art = relic.<id>` 显示对应物件主题图；新增美术只需注册AssetId并给内容加 `art` 字段。显示方式分两处：桌面立绘栏等比缩放、完整显示（`STRETCH_KEEP_ASPECT_CENTERED`），横版剧情插画缩到栏宽以内、上下留深色留白；手机面板把同一张图铺满作底图（`STRETCH_KEEP_ASPECT_COVERED`），底图统一按16:9制作，裁切落在两侧而非上下。

文本栏按 `story_step` 显示：intro 显示事件说明，choice 额外追加上一阶段结果与怪物生命/意图，result 只显示结果文字。剧情模式显示场次名与 `当前行/总行数`。文本顶部对齐，底部留白放提示。

选项栏只显示选项按钮，用等量弹性间隔均匀分布，按钮不再堆在顶部、底部不再留整块空白。桌面在栏顶固定一行：左侧说明文字「请做出选择」，右侧仅在预选时出现「取消选择」；手机不放这一行，把该处56逻辑像素的高度让给按钮（三项选项可完整显示，不再被截断）。按钮仍由原生 Button 承担文字、禁用原因、焦点与键鼠输入，长名与费用自动换行。

选项采用两步选择：首次点击只进入预选，右侧该选项文字变为「确认」，文本栏换成该选项的标题、说明、消耗与方式；再次点击同一选项才提交真实命令。预选后可用「取消选择」退出：桌面是栏顶右上角的红字，手机是该选项右端内侧的红字（避开右侧菱形装饰，保留56逻辑像素高触控区）；两处都是无背景、边框或装饰的纯文字按钮，点击即退出预选并恢复事件说明。桌面该行高度在两种状态下都保留，因此取消文字出现/消失不会推动其他选项的位置。

「继续」「跳过文字」「结束节点」「继续剧情/完成这段剧情」「迎战」「离开遭遇」「进入商店」是一步动作，点击即提交，不进入预选。

预选时若选项带目标筏格，会在木筏上高亮该格；取消预选或关闭事件时清除高亮。高亮复用事件遮罩下的专用拾取代理，不写规则状态。

规则阶段、AP、选项条件、结果命令与随机流保持原契约；三栏布局、预选状态、取消按钮都是表现状态，不进入 GameState，也不写入存档。验证见 [事件三栏验证](../evidence/node-event-ui-verification.md)。
