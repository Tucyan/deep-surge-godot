# 手机 UI 可读性排查与优化建议

状态：排查完成，以下改动均为提案，尚未实施。日期：2026-10-19。

核对对象：`codex/origins-v1` 当前工作树（包含已有未提交修改）。本次不修改游戏运行代码、不重新打包 APK。

## 为什么 125% 仍然小

1. `project.godot` 使用 1600×900 设计画布；`presentation/display_settings.gd` 的 UI 倍率设置的是 Window.content_scale_factor，不是手机物理字号或触控尺寸。相同逻辑尺寸在不同屏幕上的观感不同。
2. 手机普通按钮皮肤主要增加上下内边距，设置适配主要把按钮高度提高到56；没有一起抬高按钮字号。公共 Theme 默认16，设置行标题15、说明适配后最低14，依然容易出现大框小字。
3. 部分页面另做整体缩放。独立剧情使用1600×900整幅构图适配，手牌按容器高度缩放。局部的 fit 可以抵消全局 UI 放大。
4. 高频工具入口另换皮肤并去掉公共内边距，不享受普通文字按钮的加厚规则。

逻辑字号、逻辑高度不能直接当成 Android dp/sp。本报告提出的逻辑值仅为第一轮设计目标，最终须在真机上校准。

## 设置整页的具体方案

- 仅手机启用整页布局，桌面继续使用现有弹窗；首页和局内使用同一个设置内容组件。
- 整页覆盖游戏画面，在安全区域内放置固定标题栏：“返回 / 设置”；Android系统返回与标题栏返回执行同一层级的导航。
- “显示 / 游戏 / 剧情”保持可见，可用横向页签或左侧分类；正文区域独立纵向滚动。
- 每项设置采用“名称与当前值”第一行、“说明”第二行，控件过宽时放到下一行。移除中英双标题和装饰性副标题，让出阅读空间。
- 第一轮逻辑目标：页标题28～32，设置名称20～22，说明18，按钮文字20～22，主要行高72～88，普通按钮至少60高、图标命中区至少56×56，间距12～16。须结合中文字体度量、换行和真机密度调整。
- 滑条提供足够大的滑块与触摸区域，增加减/加按钮或档位入口，允许单击调整，避免只能精确拖动细轨道。
- 下拉框不仅扩大闭合控件，也扩大展开后的菜单字号与选项高度；开关使整行可点击，显示“开启/关闭”文本。
- 返回首页放到单独的航程管理区域；放弃本局放在更下方的危险操作区域，保留现有规则约定的确认流程，不占据所有设置页的固定阅读空间。
- 调整 UI 时尽量保留当前分类、滚动位置和焦点；返回恢复原游戏视图。打开、浏览、调整及返回不得推进游戏或改变AP、随机流、剧情进度。

## 进一步优化

1. 手机建立独立布局密度：标题、正文、注释、按钮文字统一令牌；自绘HUD数字也使用这些值。不能只在页面结束后递归加大所有Label，避免破坏卡牌与固定框布局。
2. 分开“文字大小”和“界面大小”：文字设置负责阅读，UI设置负责控件与留白。先消除固定列数与fit抵消，再评估扩大UI范围到150%；直接提高倍率上限可能挤压手牌与正文。
3. 中文可读性以实际字体字面、行距、背景对比为准。暗背景说明少用过淡文字；装饰框/罗盘缩减，优先让按钮文字占据有效面积。
4. 不依赖悬浮提示：手机端清除tooltip后，缺少AP/材料、属性名称、操作说明要有可见替代入口。禁用按钮不能成为说明的唯一入口。
5. 阅读与操作分开：详情页承载长文，高频页面只展示本次决策需要的信息，减少同屏并排面板，保留清楚的返回路径。

## 实施后的验收建议

- 先使用1260×540、1280×720、1680×720、2520×1080等横屏窗口模拟，覆盖100%和125%，以及后续新增的文字档位；每档检查换行、遮挡、正文剩余高度与按钮命中区。
- 真机覆盖不同屏幕尺寸/密度，校准视觉字号和触控目标。加入刘海/挖孔安全区域、系统返回、手势导航边缘及下拉弹出菜单检查。
- 完整路线：首页→设置三分类→新局→航行→事件→战斗→手牌详情→合成/转化→商店→图鉴/遗物→剧情/LOG→结算；包括长文本、缺料、禁用原因、多手牌、多遗物与多存档。
- 验证设置返回原上下文，缩放后保留分类与滚动位置，操作不穿透场景；对照前后GameSession状态与随机流。
- 通过标准应同时包含“看得清、点得准、关键说明无需猜测”，不能只检查控件没有越界。
