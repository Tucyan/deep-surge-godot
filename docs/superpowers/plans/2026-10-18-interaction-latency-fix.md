# Interaction latency repair

Goal: eliminate the measured full HUD rebuild for combat selection, camera toggle and game modal open/close; prevent stationary card clicks from being canceled by visual animation. Preserve rules/RNG, read-only gallery, intro flags, save schema, blocked controls and stale-command protection.

1. `tests/test_interaction_refresh.gd` and `test_hand_animation_click.gd`: first run must fail on HUD identity/modal processing and stationary-pointer animation. Actual initial results: 25 identity/lifecycle failures and 3 gesture failures, no parser errors.
2. `flow_app.handle_ui`: persist battle UI selection locally and update the live HUD context; camera toggle updates existing HUD icon/tooltip through `voyage_hud.refresh_camera_mode`. Retain full render fallback if no compatible HUD exists.
3. `flow_app`: extract existing modal construction into one shared builder. Keep the base page, modal root, active panel ID, base-state/layout signature and exact disabled button states. Game-only `render()` fast path reconstructs just the modal layer when state/layout signature is unchanged. Full render remains mandatory when rules/profile/layout change. Freeze base hand/interaction input while modal; restore prior state and fresh revisions when closing. Requote raft actions after panel revision changes. Modal content and tutorial banners retain existing layout rules.
4. `hand_fan`: capture `press_origin = point` at pointer-down. Compare mouse/touch motion to this immutable position; accept stationary release within 10px even if card animation moved the mesh. Keep outside, disabled, drag, focus-loss and touch-cancel guards.
5. Run targeted headless tests, existing combat/gesture/mobile/settings/navigation tests, then graphical `probe_interaction_latency.gd` using isolated APPDATA and separate after output. Require real mouse callbacks, first-draw state, retained HUD on optimized paths and no failed inputs. Preserve previous raw failure evidence. Validate multi-resolution/UI-scale layouts and pointer occlusion with actual rendering.
6. Independent review and relevant core/story/save/recall regressions; fix actionable findings and rerun affected checks. Cold panel profiling found eight synchronous texture loads totaling about156ms. Add `asset_catalog.warm_textures` with `ResourceLoader.load_threaded_request`, readiness checks and at most one finalized resource per frame; `_warm_craft_art` starts one first-page batch from graphical startup. Keep normal texture fallback and owner-lifetime checks. `test_asset_warmup.gd` must first fail for the absent method, then verify yielded work, resource reuse, ignored IDs, canceled owner and unchanged rules. Save measured before/after data, observed limitations and review outcome. No automatic commit, push, dependency installation or release export.

Runtime commands use the installed Godot 4.7.2 console binary with `--path deep-surge-godot --script res://tests/<test>.gd`; only pure logic tests use `--headless`. Long command retries are limited to 3; timeout goes to the user unless they explicitly request another attempt.
