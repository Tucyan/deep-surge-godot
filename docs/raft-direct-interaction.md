# 木筏直接交互 · 2026-10-15

适用当前 Godot 工程，复用已有 install / fuel / upgrade / repair_cell / action_card / expand 命令，不新增规则或材料费用。

## 操作

- 导航、准备及收尾等现有可进行基地操作的阶段：设备牌长按 0.2 秒进入拖动，移出手牌区后可拖向木筏完好空格。空格显示蓝色筏格与设备虚影；AP 或教学限制不允许时为红色。松开鼠标或同一手指后，在指定格安装该 UID 的设备，原规则扣 1 AP。
- 同类设备牌拖到完好格上的同类 1 级设备，可合并升级至 2 级，消耗所拖设备牌及 1 AP。允许升级时显示纯绿色半透明填充，不显示边线或额外设备虚影；等级/AP/教学限制仍由原 upgrade 命令校验。手牌设备按 1 级处理，不能直接与 2 级设备合并；高等级仍在详情面板执行同级已安装设备合并。
- 木材、怪物尸体长按后可拖到完好筏格上的已安装灯，蓝色虚影表示允许添加；松开后仅消耗所拖 UID 的一份物资（含堆叠），木材增加 1 点、尸体增加 3 点燃料，不消耗 AP。海面、其他设备和破损灯不消费；装饰灯不属于功能目标。
- 普通物资拖动继续理牌；设备、燃料在手牌区内也继续理牌。设备拖到海面、不同类占用格、破损格或不可用位置，原牌回位，不改变手牌顺序。Esc、系统触摸取消和失焦清除拖动/虚影，不消耗物资。
- 点击在位筏格显示纯白色半透明高亮（没有额外边线）及就近的紧凑面板；再次点击同一格取消高亮并关闭面板。只按该格与手牌提供安装、升级、修复；来源不止一种时用下拉选择，不为每个材料实例堆按钮。按钮显示真实费用/禁用原因，右上 X 取消选择。原木筏详情入口保留，灯燃料、治疗、拆除等原操作仍可在那里执行。
- 已安装设备始终显示升级操作；缺少同类牌/同级设备、AP 不足、破损、满级或教学限制时禁用，并在按钮下直接显示原因，不依赖悬停。1级设备另提供“一键升级”，列出配方物资和制作 AP＋升级 AP；满足原制作条件后一次消耗配方物资及两步 AP（现有配方合计 2 AP），直接升到2级。2→3级仍需另一件同类2级已安装设备。面板左边缘位于选中筏格及设备投影宽度的80%处，允许覆盖右侧1/5，横向随镜头与UI倍率跟随；纵向固定在选中筏格投影高度，不进行顶部、底部或 HUD 遮挡检测，因此视口空间不足时可能与 HUD 或手牌重叠。
- 没有可安装的完好空格时提示扩建。始终只显示一个按行列顺序选择的合法邻接位置，排除装饰筏根、在位格和范围外位置；建出空格后提示消失，下次满筏再提供下一个位置。不会自动扩大核心 3×3 / 已解锁 4×4 范围。
- 可建设的扩建虚影为蓝色，物资/AP 或教学条件不足为红色。首次点击只显示“木头 2 / AP 1”消耗及禁止原因，点击“确认新建”才派发 expand；X 或点击空白取消，不消费。过期确认由原 revision 校验拒绝。
- 按最新反馈，新建蓝/红虚影改为与海面同高：采样位置及周边共 9 点，贴在局部最高海面上方 0.025 m，竖向厚度压为 10%，不再固定挂在筏面高度。始终只显示一个，点击确认时也不叠加第二层金色模型。设备拖放与在位格选中效果仍跟随筏面。虚影不计逻辑格、设备、镜头构图或海面接触。
- 红色、蓝色提示新增同色填充面，不透明度 0.16（84% 透明），轮廓线仅横向宽度放大 1.4 倍、保持长度与位置。白色选中和绿色升级只显示不透明度 0.24 的纯色填充，不实例化线框模型；从实际 Deck 模型提取朝上表面，沿木筏局部上方偏移 0.002 m 防闪烁，保留木板间隙、边缘及破损形状，随筏格倾斜，不再使用固定高度的悬空平面。表面网格按甲板模型变体缓存、白绿共享；红蓝填充仍使用原平面。节点随提示释放，原 Blender 模型不变。
- 船上月光与装饰灯的实时阴影保留，但不透明度从 1.0 降至 0.4，减淡设备投影；不通过整体提亮海面替代阴影调整。夜海配置见 toon-ocean.json 的 environment.shadow_opacity。
- 扩建/设备变化后重新计算实际网格包围盒，并按顶部菜单、右侧操作框、底部手牌及容量徽章留出的区域自动居中、拉远。摄像机在 0.65 秒内平滑过渡，重入操作从当前姿态继续；普通波浪不触发反复重构图。UI 倍率改变也按新的布局重新适配。

## 实现边界

- `raft_actions.gd` 从只读 session view / snapshot 建立操作报价。候选操作在恢复出来的 GameSession 副本上执行原规则校验，缓存到本次界面；不 dispatch 到活动局，不改变活动局 RNG、统计或实例。
- 扩建费用从 `run_rules.gd` 导出的 EXPANSION_COST / EXPANSION_AP 读取。提取常量不改变木头 2 / AP 1 的既有数值。
- `fuel` 增加可选 `uid` 参数：提供时校验物资种类、存在性及非临时实例，并准确消耗该实例；省略时沿用按 `material` 消耗一份的接口。重复提交已消耗 UID 会失败，费用及燃料数值不变。
- `upgrade` 增加可选 `craft: true` 参数：同一次 dispatch 内调用原 craft 后，将新生成设备牌作为1级合并来源；两步间不触发自动结算。失败由原事务整体回滚状态、物资、AP、统计及发现信息，过期 revision 仍拒绝；沿用配方、科技和外层升级教学限制，燃料与生产进度保持，制作记录和升级统计均保留，AP只计一次。不是新的升级平衡规则；普通 UID/筏格设备合并接口保持。
- `raft_surface.gd` 把 UI 坐标映射至实际渲染视口，通过相机射线拾取设备网格/筏面；使用木筏局部坐标跟随倾斜。相同映射支持 UI 倍率与清晰度变化。装饰筏根始终不是功能格。
- `raft_interaction.gd` 接收手牌拖放信号、组合小面板与确认；通过原 GameSession 命令完成事务。只有无模态面板且可基地操作时启用，打开设置/详情或换页即清理全部虚影。
- 虚影独立挂在 3D world 下，跟随 raft 变换；不加入 raft 的镜头包围盒。模型网格和材质由现有缓存共享，页面私有实例随移除释放，没有新增碰撞体或遗留拾取代理。

见[当次验证记录](../evidence/raft-interaction-verification.md)。鼠标和触摸事件在 Windows 上验证；不是 Android 真机验收。按用户要求不进行 Android 打包，原宽屏/全屏留白问题不在本次处理范围。
