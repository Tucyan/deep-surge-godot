# 显示与 UI 大小设置

2026-10-15。本次解决移动端 UI 太小，新增首页右上角“设置”；游戏页沿用已有“设置”入口。没有修改规则、内容或存档版本。

## 已实现

- UI 大小使用滑动条，范围 100%～125%、步进 1%；拖动时显示百分比，松开后应用并保存，避免拖动中重建控件。支持键盘方向键微调并保留焦点。手机首次启动默认 125%，电脑默认 100%。通过 Godot Window.content_scale_factor 调整文字、按钮和卡牌；首页图片按钮同时按比例放大，背景仍铺满。
- 四项生存属性在所有倍率下始终保持一行；阶段/事件区保留手牌上方空间。合成占满整个逻辑画布，固定四列两行、每页最多 8 个配方。翻页仅改变表现状态。
- 游戏页左上菜单和设置中保留“返回首页”。其他面板的导航退出只显示右上角“X”，不再显示“关闭面板”“暂时收起”或“返回首页”。新局步骤、卡牌详情、结算和独立剧情 LOG 的关闭也使用 X；内部配方翻页、日志回看及商店离开等玩法动作保留。
- 手机只显示“清晰度”：流畅（场景宽高各 50%）、均衡（75%）、清晰（100%）。仅调整海面/木筏的 SubViewport，文字、按钮、卡图和首页视频不随清晰度模糊。
- 电脑显示分辨率与全屏。分辨率档位：960×540、1280×720、1600×900、1920×1080、2560×1440。窗口模式调整窗口大小，并限制在当前屏幕可用范围；全屏保持显示器原生模式，以所选分辨率限制场景渲染高度，UI 保持清晰。全屏分辨率不会强制切换显示器硬件模式。
- 显示页新增桌面/手机共用的“帧率上限”：30、60、90、120 FPS、无限制，默认60。选择后即时设置 `Engine.max_fps`，无限制映射为0；使用该选项管理上限并禁用窗口 VSync，避免另一重上限覆盖用户选择。实际帧率仍取决于设备及系统。`fps_limit` 独立保存，旧配置或非法类型/档位回退60，不修改显示器刷新率或游戏规则。
- “显示 / 游戏”分页；原有海面动态、自动理牌、叠牌及放弃本局保留在“游戏”。不新增滚动容器。
- UI 倍率松开滑条后应用，其他选项即时应用。显示与动态设置保存到 `user://display-settings.cfg`；手牌设置仍存原独立配置。关闭设置、调整 UI 和画质不改变 AP、物资、剧情游标、种子或随机流。

## 实现边界

`presentation/display_settings.gd` 管理平台判断、配置读写、窗口显示和场景尺寸计算；`presentation/settings_panel.gd` 管理设置控件；`flow_app.gd` 组合并在尺寸变化时更新场景视口。GameSession 不持有设置或界面对象。

场景显示通过全屏 `TextureRect` 将独立 `SubViewport` 的渲染纹理映射到完整逻辑画面。渲染像素数只控制清晰度，不控制纹理在屏幕上的占位尺寸；切换 UI 倍率及清晰度后木筏保持原屏幕位置。

全局仍沿用项目原有画面比例策略。窗口太小时文字的实际物理尺寸仍受屏幕限制；本次开放并验证的最大 UI 倍率为 125%，没有宣称任意倍率/比例都已适配。
